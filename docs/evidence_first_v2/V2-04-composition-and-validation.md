# Evidence-first V2-04 composition and validation

V2-04 is an offline, injected-composer contract. It binds every retained V2-02 request field to the externally held request, makes one canonical post-handoff request (including the validated directory market), then derives the sole allowed V2-03 branch and fresh, unique, source-sorted facts. A supplied `COMPLETE` is never answer authority.

The composer receives only the current message, scope, accepted facts, attempt number, and structured prior failures. It receives neither source documents nor conversation history. Its output is untrusted: the final answer must exactly render every accepted fact once and each citation must equal that fact's accepted source reference. This preserves short numbers and all existing V2-03 role, unit, timing, exception, version, language, and branch bindings. A company-policy fact cannot satisfy sponsoring scope because V2-03 revalidates the branch scope first.

The public result contains only bounded status, answer, citations, codes, and invocation count: no rejected output, exception text, trace, or provider object. An optional application-owned diagnostic sink receives codes only. Composer exceptions and wrong return types become a sanitized fault code. It allows one correction invocation only; correction sees codes only and faces identical gates. Missing coverage produces a safe partial, compound/invalid handoffs clarify, and failures have deterministic codes.

Refusal is a separate fixed-text, no-fact public outcome. It is permitted only for a bounded high-risk request subject; arbitrary provider refusal prose, claims, and citations have no authority. A false refusal receives the one correction opportunity. A small normalized structural safety check removes Unicode format characters, preserves `income is not guaranteed`, `learning`, and `treat customers`, and blocks affirmative `make $500 every day`, guaranteed-income, and diabetes-elimination forms. It is deliberately not a general semantic classifier or safe-question exemption.

Format characters are inspected before normalization: a format-bearing risk form is unsupported and blocks rather than joining tokens into a ready answer. The same bounded gate recognizes the documented Cyrillic-i `іncome` confusable form. Claim and citation indexes require actual integers, never booleans. Facts not used by the current request's governing aspects reject before composition; same-scope but unrelated source facts cannot be rendered.

Explicit `not`, `no`, and `never` governing the bounded refusal patterns prevent a refusal and use the single correction path. Mixed Latin/Cyrillic output is unsupported and blocks. Fact selection uses the exact V2-03 requirements (including trusted manifest mandates and alternatives), not generic qualifier labels.

Refusal matching and its negation check share one bounded original-request separator view, including format characters, dash punctuation, and enclosing punctuation. Script mixing blocks only when Latin and Cyrillic occur in one token. Composition selects one canonical witness per V2-03 singleton or alternative obligation; redundant witnesses are excluded before exact claim/citation rendering.

The shared refusal view also treats colon and slash as separators and assesses each bounded positive phrase independently. Safety exceptions are clause-local, so a benign or negative clause cannot exempt a separate income/medical clause. Cross-section manifest alternatives retain their single V2-03 group identity during witness selection.

Safety clause boundaries are deliberately limited to semicolon, comma, colon, slash, period, exclamation, question mark, LF, and CRLF. CRLF is consumed as one boundary. This is not general sentence parsing.

This is structural offline validation, not semantic entailment, retrieval, translation, real composer/model, production, or live-quality proof. The strict exact-claim renderer deliberately limits prose generation until a later approved semantic validation stage.
