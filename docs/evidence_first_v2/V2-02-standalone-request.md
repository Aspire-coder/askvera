# Evidence-first V2-02 standalone request

V2-02 is an offline, bounded contract around an injected fake or replay interpreter. It has no model, provider, network, cache, session store, or production adapter.

The standalone message is exactly the current request. The builder passes the interpreter a rebuilt `V2Request` with `turns=()` and no requested directory market, plus only bounded `StructuredContext`; raw request turns cannot bypass the context limit. Context retains a contiguous newest suffix of at most 32 turns and 4,000 characters. If the newest turn is too large, history fallback is blocked rather than reviving older context. Every assistant-turn `ContextUse` is rejected in V2-02. Structured assistant-state is explicitly deferred to a later milestone.

The place registry is a required, defensively copied, sorted immutable tuple. It has finite entry and alias limits and publishes a deterministic SHA-256 identity. Matching scans original request code points and returns only exact, case-safe registered aliases with Unicode-letter/digit token boundaries. Unsupported normalization, full-width/decomposed forms, adjacent letters/digits, unregistered destinations, and registry ambiguity do not resolve or inherit a prior market.

History market fallback is intentionally limited to the positive continuation grammar `telephone`, `phone`, `contact`, or `what about [the] telephone|phone|contact`, with no registered current alias. It requires exactly one value-bound use from the newest retained user turn, and that turn must contain exactly one resolved registry destination. A newer unrelated, unknown, or multi-destination user turn blocks fallback rather than reviving an older market. Any other directory-like request without a registered destination requires structured clarification and retains no history market.

The bounded channel vocabulary recognizes policy/eligibility/sponsoring permission and directory telephone/contact/office/hotline/switchboard/email/address/WhatsApp forms, including the documented `Puis-je parrainer au ...` form. Clauses split on English `and` or `or`, comma, or semicolon. Every nonempty unsupported branch beside a recognized branch requires compound clarification; `fax` and `SMS` are not supported channels. A numeric/unit continuation such as `8 and 8.5 units` remains one policy request. A clearly negated `do not want eligibility/policy/sponsoring/recruiting ..., only ...` branch is suppressed. This is not a general multilingual parser.

Output is capped for request text, registry entries and aliases, numeric tokens, context uses, ambiguities, and ambiguity detail. Registry aliases reject control characters and registry identity uses sorted UTF-8 length-prefixed fields. Original matched source value and span travel separately from the canonical registry alias, so supported lowercase/uppercase forms resolve with source-exact provenance. Unicode letters, digits, marks, and connector punctuation are token continuations. Ambiguity detail is a fixed canonical string for its code, so arbitrary free text cannot become a structured output side channel. Current numeric provenance must be an ordered set of distinct original spans, including repeated occurrences and ASCII decimals.

`resolve_standalone_scope` is the only exported V2-02-to-V2-01 handoff. Builder results carry a private fingerprint over all scope-relevant fields. The handoff recomputes clarification and destination invariants, rejects direct or modified results, and rejects every clarification result and every international request without a validated directory market before rebuilding a request and calling V2-01 `resolve_scope`.

These are local structural guards with adversarial fake outputs. They do not establish registry completeness, real interpretation, retrieval, evidence grounding, translation, answer quality, live behavior, improvement, or release readiness.
