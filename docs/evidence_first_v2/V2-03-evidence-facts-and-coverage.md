# Evidence-first V2-03 evidence facts and coverage

V2-03 is an offline structural provenance contract. Catalogues and their governing manifests are trusted application configuration. Source documents, document annotations, provider candidates, and fact wrappers are untrusted data. Python classes are data contracts, not security capabilities.

All V2-03 identities use one typed canonical encoder: each value has a type tag, tuple cardinality, and UTF-8 byte length for every string. The encoder is used for annotation, manifest, catalog, request, scope, branch, and fact identities. Delimiters, controls, and nested tuples cannot merge identities such as `("x,eligibility",)` and `("x", "eligibility")`.

`SourceCatalog.admit` validates and freezes source sections plus a separate `GoverningManifest`. Document `required_for` and `alternative_group` fields are rejected: they cannot weaken default obligations. The manifest can add an obligation or authorize an alternative only when it references an exact admitted source annotation and an existing target aspect. Duplicate requirements, conflicting group assignments for one exact annotation/target, reused group names across targets, ghost cross-section authorizations, and one-section names in `cross_section_alternatives` reject. Alternative groups are section-local by default; a trusted manifest must name each real, unambiguous, multi-section group explicitly. Defaults remain mandatory: for a requested aspect, the matching annotation plus role/unit/timing/exception conditions in every governing section are required.

Admission uses one Unicode-aware token-boundary rule. Unicode letters, numbers, marks, and connector punctuation continue a token. Numeric annotations also reject adjacent signs (`+`, `-`, U+2212) and bounded numeric/range context (`/`, hyphen/dash, `:`, decimal comma/dot). Therefore fragments such as `8` from `18`, `8.5`, signed values, ranges, `8` plus a combining mark, or `8` plus UNDERTIE reject. Affirmative fragments reject when immediately preceded by `not`, `no`, or `never`, including bounded hyphen, colon, or slash punctuation forms; `eligible` from `not-eligible` and `ineligible` therefore reject. Full standalone values such as `value 8 units`, `(8)`, and multilingual `éligibilité` remain valid.

`assess_coverage` receives the externally held actual `V2Request`. It recomputes the V2-01 scope and every bounded current-message obligation at assessment time. A `CoverageBranch` is only a compatibility marker: a builder-minted substituted request, omitted request content, direct replacement, or stale scope cannot substitute the externally supplied request. Facts are revalidated against the current catalog and scope before coverage. Missing conditions, missing governing sections, missing evidence, or unsupported request extraction reject or remain `UNCERTAIN`; they never create a supported fact.

This remains structural binding, not semantic entailment. It does not prove source completeness, retrieval quality, multilingual interpretation, translation correctness, generated-answer correctness, live behavior, production readiness, or release readiness. No universal policy checklist, ontology, general semantic parser, or V2-04 behavior is introduced.
