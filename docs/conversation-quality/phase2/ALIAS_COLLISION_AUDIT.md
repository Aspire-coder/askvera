# Alias / closed-class function word collision audit

## Defect

`config/market_name_aliases.json` is generated from Unicode CLDR
(`"source": "Node Intl.DisplayNames / Unicode CLDR"`) and lists, per market,
every locale's own name for that country. It lists `"Tai"` (Estonian for
Thailand) as an alias for `TH`. `"tai"` is also the everyday Finnish word for
"or", so an ordinary Finnish question containing it named Thailand as a
directory target:

```
_directory_target_country_names("Voinko maksaa kortilla tai käteisellä?", "FI")
-> {'Thailand'}   # before this change
-> set()          # after this change
```

## Guard

Implemented at the alias-loading layer:
`services/market_config.py`'s `_localized_market_names()` now filters the raw
`market_name_aliases.json` names through
`config/alias_function_word_guard.filter_function_word_aliases()` before
returning them to every consumer (`find_market_mentions`,
`_all_configured_market_names`, and everything built on either). An alias is
excluded only when, as a whole word, it equals a closed-class function word
(conjunction, preposition, article, pronoun or auxiliary) already listed in
this repository's own reviewed vocabulary:

- `config/reference_vocabulary.py`'s `LOCALIZED_NON_CONTENT_TOKENS`
- `app/orchestrator/chat_orchestrator.py`'s
  `LOCALIZED_FOLLOW_UP_FUNCTION_WORDS` and `LOCALIZED_FOLLOW_UP_STOP_WORDS`

plus a small, explicitly-documented supplement in
`config/alias_function_word_guard.py`
(`_SUPPLEMENTARY_CLOSED_CLASS_FUNCTION_WORDS`) for closed-class words proven
necessary by this audit but not yet present in either reviewed vocabulary:
Finnish `"tai"` ("or") only.

Every exclusion is logged (`market_alias_function_word_collision_excluded`,
WARNING level, via `services.market_config`'s logger) when
`_localized_market_names()` loads, and is independently reproducible offline
via `filter_function_word_aliases()` (unit-tested in
`tests/unit/test_market_alias_function_word_guard.py`).

`config/market_name_aliases.json` itself is untouched - it is generated by a
scheduled process and is not hand-edited.

## Full scan result

An offline scan (`filter_function_word_aliases()` run over the entire, real
`config/market_name_aliases.json` - 155 markets, 3,232 aliases) against the
combined closed-class vocabulary above (353 distinct normalized function
words, before the supplement) found **zero** collisions from the reviewed
vocabulary alone. Adding the one-entry Finnish supplement (`"tai"`) finds
exactly **one** collision in the entire file:

| Market | Alias | Normalized form | Closed class | Source |
|---|---|---|---|---|
| TH | `Tai` | `tai` | Finnish coordinating conjunction ("or") | supplement (not yet in either reviewed vocabulary) |

**"Tai" is the only collision found.** No alias in any market collides with
any function word already present in `LOCALIZED_NON_CONTENT_TOKENS`,
`LOCALIZED_FOLLOW_UP_FUNCTION_WORDS`, or `LOCALIZED_FOLLOW_UP_STOP_WORDS`.

## Positive controls

- `"Thailand"`, `"Tailand"`, `"Tailandia"` still resolve to `{"TH"}`.
- The Finnish spelling a user would actually write for Thailand,
  `"Thaimaa"`, still resolves to `{"TH"}`.
- A sample of 10 other markets (Finland, France, Germany, United Kingdom,
  Kenya, Mali, Chile, Peru, Togo, United States) still resolve to their own
  code by their common English name.

## Known limitation - accepted, not fixed here

Some market aliases are real country names in one language and an ordinary
content noun (not a closed-class function word) in another - e.g. Chile /
"chili" (the pepper, English), Turkey / "turkey" (the bird, English), Mali
(no known English-content collision, but the same shape). These are **not**
excluded by this guard, and must not be: a content word is not a member of
any closed grammatical class, so silencing it here would hide genuine
country-name ambiguity behind a rule meant only for grammatical particles.
This is a pre-existing, accepted limitation of alias-based market detection,
unchanged by this fix.

Coverage is also bounded by which languages this repository's own vocabulary
tables cover (`en`, `fr`, `de`, `nl`, `it`, `pt`, `es`, `fi`, `no`, `sv`, plus
`ru`/`sr`/`da` for the chat_orchestrator follow-up tables). A market
configured with a language outside that set (e.g. `ar`, `sq`, `et`, `lv`,
`lt`, `bg`, `hr`, `el`, `cs`, `ka`, `kk`, `mk`, `ro`, `uk`, `tr`, `pl`, `sk`,
`sl`, `he`, `ku`, `uz`, `az`, `hu`) has no closed-class vocabulary this guard
can check against, so a collision in one of those languages - if one exists
- would not be caught. The full scan above found none for the languages this
guard does cover; extending coverage to the rest would require this
repository to first build and review a closed-class word list for each of
those languages, which is out of scope for this change.
